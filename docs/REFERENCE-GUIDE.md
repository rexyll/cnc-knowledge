# 来源、证据与引用规范

> 适用范围：全库22个知识章节
> 规范版本：1.0
> 关联模型：docs/data-model/source.schema.json

## 1. 目标与基本原则

本规范用于确保知识库中的技术事实可追溯、可复核，并能区分规范要求、厂商声明、第三方测试、现场数据和工程判断。

1. 重要事实应在其出现位置提供来源引用；不能只在文章结尾罗列无法对应具体结论的链接。
2. 数值、规格、材料性能、报警代码、兼容性、维修步骤、标准条款和安全要求必须能追溯到具体资料位置。
3. 所有引用统一指向SRC来源记录；来源文件是否保存为ASSET由版权、许可和项目归档规则单独决定。
4. 来源权威等级与证据性质分开记录。官方资料可以权威地证明厂商发布了某项规格，但不自动构成独立实测。
5. 无法验证的内容应标记待核实；多个来源冲突时保留差异，不自行拼接出一个看似精确的答案。

## 2. 来源权威等级

| 等级 | 定义 | 常见来源 | 使用规则 |
|---|---|---|---|
| A | 直接责任机构或原始发布主体 | 法规/标准发布机构、政府监管机构、机床或部件原厂正式手册、规格书、图纸、版本公告 | 适合引用规范文本、官方产品声明和厂商规定；标明声明性质 |
| B | 可追溯的专业研究或独立验证来源 | 同行评审论文、大学/研究机构报告、认可实验室报告、可追溯的独立测试 | 适合技术机理、测量方法和独立试验结果；说明实验对象与条件 |
| C | 可靠专业出版与行业资料 | 权威技术书籍、专业协会资料、成熟工程出版物、行业会议论文 | 用作背景和解释；关键参数仍应回到原始来源 |
| D | 二次整理或商业资料 | 专业网站、经销商资料、咨询文章、新闻和非原始技术介绍 | 用作检索线索或辅助说明，不宜单独支撑高风险结论 |
| E | 社区与经验资料 | 论坛、问答、用户视频、个人博客和经验帖 | 用于发现问题和工程经验线索；须标明个体经验，不可泛化为通用规范 |
| unknown | 无法判定 | 来源信息不足或来源真实性未核验 | 只能作为待核实线索 |

等级描述的是来源的权威性和可追溯性，不是对每句话真实性的自动评分。即使来源为A，也要核对版本、适用机型和上下文。

## 3. 证据性质

在来源记录的evidence_kind字段中选择最贴近的一项：

- normative_requirement：标准、法规或规范中的要求。
- manufacturer_declaration：厂商公开声明的参数、能力或兼容性。
- official_documentation：厂商说明书、用户手册、技术手册或官方帮助文档。
- independent_test：第三方独立测试或检测数据。
- academic_research：学术研究、模型、实验或论文结论。
- engineering_measurement：具体设备/现场的实测结果。
- engineering_experience：工程经验、维修记录或现场观察。
- secondary_summary：第三方二次整理、转述或科普材料。
- community_experience：社区用户经验、讨论或视频演示。
- other：其他，需要在备注说明。

一条来源可能同时具有多种内容属性；如有必要，建立多条来源记录或在备注中区分具体页面/章节，不把不同性质的证据混成一个结论。

## 4. 行内引用格式

正文采用项目统一引用标记：

- 单一来源：〔SRC-000123，§4.2〕
- 页码定位：〔SRC-000123，p.18〕
- 表格/图纸定位：〔SRC-000123，表6 / 图3〕
- 多来源：〔SRC-000123，§4.2；SRC-000124，p.7〕
- 无页码网页：〔SRC-000125，页面标题/小节名称，访问于YYYY-MM-DD〕

以上为引用格式示例，不代表真实来源。

引用应紧跟被支持的陈述；不要将同一引用放在长段落末尾，让读者无法判断它支撑哪一项事实。一个表格中不同来源的数据应逐行引用，或设置“来源ID/定位”列。

## 5. 数值与技术参数的引用要求

每一个关键数值应尽可能同时记录：

- 对象：具体机床型号、部件型号、材料牌号或软件/固件版本。
- 参数名称、数值、单位、数据属性（额定、最大、典型、选配、实测或估算）。
- 条件：温度、负载、行程、测量位置、工况、试样状态、配置和测试环境。
- 方法：标准、试验方法、仪器、计算方式或厂商定义。
- 来源ID及页码、章节、表格、图号。
- 数据核验日期和版本有效性。

不得将不同配置、不同版本或不同试验条件下的参数直接并列比较；不能确认可比性时应明确说明。

## 6. 来源记录与仓库路径

- 来源元数据存放于docs/data/sources/SRC-xxxxxx.json。
- 实体记录引用source_ids；关系记录引用source_ids。
- 实际归档的本地文件另建ASSET实体记录，并放在resouces对应章节目录。
- 外部网页、标准目录或受版权限制的资料可以只有SRC记录，不要求一定保存完整副本。
- 具体来源记录字段以source.schema.json为准，至少包含标题、发布主体、类型、版本、访问日期、权威等级、证据性质和权利状态。

## 7. 来源冲突与更正

1. 不同来源的参数或结论不一致时，先检查机型、地区、发布时间、软件版本、选件和测试条件。
2. 无法消除冲突时，在文章中并列呈现各来源及差异，并把核验状态设为disputed或in_review。
3. 发现错误时记录受影响条目、旧值/旧解释、新证据、变更原因和更正日期。
4. 不删除仍具有历史意义的旧来源；停产/废止资料可以保留，但必须标记时效状态。
5. 来源链接失效时优先寻找发布机构的归档页或替代版本；不能确认时保留失效记录并标记待核实。

## 8. 版权与安全边界

- 引用来源不等于获得转载授权；不得未经许可上传完整标准、付费手册、厂商图纸或受限文档。
- 只有有合法保存依据的完整文件才可复制进resouces对应章节目录。
- 对无权保存的资料，记录可合法保存的元数据、简短摘要和原始链接。
- 不移除水印、版权声明或作者信息；翻译、裁剪、重绘或整理版必须明确说明。
- 安全相关操作以具体机型原厂手册、适用法规/标准和专业人员评估为准。

## 9. 发布前审查清单

- 每项关键事实是否有可定位的SRC引用？
- 来源ID是否存在，且标题、发布者、版本、访问日期、权利状态完整？
- 是否将厂商声明误写为独立实测？
- 是否记录机型、配置、软件版本和测试条件？
- 是否把二手资料、社区经验和推断明确标出？
- 图片/文件是否有许可状态并按章节归档？
- 来源冲突、过期链接和待确认内容是否有说明？
