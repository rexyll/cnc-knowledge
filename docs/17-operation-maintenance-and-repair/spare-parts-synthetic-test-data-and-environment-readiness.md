# 数控机床备件合成测试数据集与环境就绪规范

**知识条目：** KNOW-000031  
**适用范围：** CH17-T004 备件端到端验收准备  
**状态：** 通用工程规范草案（in_review）

## 1. 目的与边界

本文将备件端到端验收测试从“测试用例已定义”推进到“可受控准备测试数据和非生产环境”。它规定合成数据集的身份、对象依赖、事件时序、版本冻结、环境隔离、访问控制、证据留存、重置和清理要求，供 L0～L4 测试分层使用。

本规范是项目级数据与环境准备框架，不表示已接入或验证任何企业ERP、CMMS、EAM、PLM/PDM、仓储或采购系统。本文中的对象、事件、账号和环境均为逻辑分类，不构成对任何具体供应商产品数据模型的断言。

必须区分以下三类材料：

1. **纯合成数据：** 从规则、固定种子和项目自建生成器产生，不由真实个人、客户、供应商、设备或交易记录派生；是本项目默认选择。
2. **经批准的脱敏数据：** 只有在企业数据所有者、隐私/安全责任人和系统所有者按制度批准后，才可在限定测试范围内使用。脱敏不自动等于匿名，必须评估重识别风险和组合字段泄露。
3. **生产数据：** 不得复制到本项目测试夹具、个人工作区、公共仓库或未经批准的非生产环境。即使删除姓名或账号，也不得默认将生产快照当作合成数据。

所有本轮新增CSV均为项目原创模板，不含生产记录、真实业务ID、个人数据、凭证或供应商机密。

## 2. 数据集身份、版本和冻结

每次测试运行必须引用一个不可混淆的数据集标识及版本。至少登记：

- 数据集ID、名称、语义版本、当前状态、创建时间和负责人；
- 合成数据声明、生成器名称/版本、固定种子或可追溯种子引用；
- 夹具模式版本、对象域、对象类型、测试用例范围和依赖配置；
- 时间语义与时区策略、确定性要求、重置策略、保留期限；
- 数据分类、敏感数据扫描结果、授权/批准记录和文件校验值。

建议的数据集状态为 DRAFT、REVIEW、APPROVED、FROZEN、RETIRED；状态变化应保留审计轨迹，不得覆盖历史版本。只有测试负责人、数据所有者及所需安全/隐私责任角色完成审批，才可将指定版本标为 APPROVED/FROZEN。批准范围必须包括环境、系统、测试层级、测试用例、数据域和有效期限。

冻结后的数据集应保持可复现：生成器版本、种子引用、模式版本和输入配置不变；任何修改均产生新版本和新的校验值。不得只使用文件名或“最新版”作为测试数据身份。对随机生成器，种子值可记录在受控的测试配置中；不得把密钥、访问令牌、密码或生产连接字符串作为生成器参数写入CSV或Git。

## 3. 合成对象域与依赖关系

夹具应以“逻辑业务对象 + 可追溯的事件记录”组织，而不是把企业的事务明细强行添加为知识库静态实体。

| 对象域 | 合成对象示例 | 关键依赖与校验点 |
|---|---|---|
| 组织与位置 | TEST_ORG、TEST_SITE、TEST_WAREHOUSE、TEST_BIN | 组织/仓库作用域唯一，地点层级一致 |
| 机床与配置 | MACHINE、MINST、配置快照 | 型号族、序列范围、选件和有效配置彼此一致；均为虚构标识 |
| 工程BOM | BOM修订、位号、装配关系 | BOM版本、有效期、适用配置与部件数量/单位一致 |
| 物料主数据 | PART、PRODUCT及其修订 | 规范料号、原厂料号别名、单位、生命周期状态与适用关系 |
| 供应来源 | VENDOR测试别名、供货关系 | 仅使用虚构供应方代号，不复制真实合同、价格、联系人或交期 |
| 采购与收货事务 | 采购单/行、收货事件、收货批次 | 采购授权、部分收货、剩余量、过收边界和事件引用完整 |
| 质量事务 | 检验批、质量处置、放行事件 | 未检/隔离状态不得进入可用库存；放行需可追溯 |
| 库存事务 | 库存快照、移动事件、批次/序列、预留 | 数量、单位、状态桶、库位与事务顺序一致 |
| 维修事务 | 维修工单、领料/退料、安装消耗、旧件返还 | 设备实例、部件、工单和批次关联一致；发料不等同于安装消耗 |
| 工程审批 | 替代件申请、适用性评估、审批事件 | 机型/序列/BOM范围、批准状态和有效期可验证 |
| 生命周期事件 | PCN、EOL、最后采购窗口、影响评估 | 公告时间、适用对象、缓解措施和审批状态区分 |
| 身份与权限 | 测试用户、角色、授权关系 | 使用虚构测试身份和最小权限；不复制企业真实用户目录 |

主数据/静态配置与采购单行、收货、质量检查、库存流水、预留、维修工单、审批实例等业务事务必须分开表达。事务可作为测试系统的原生记录或事件日志；项目仓库仅保存测试夹具、关系索引和证据摘要，不因此扩展全库实体Schema或关系谓词。

### 3.1 依赖和一致性顺序

建议按以下依赖层级构造数据，而不是任意拼接孤立记录：

1. 组织、站点、仓库和测试身份；
2. 虚构机床型号/实例、配置快照与BOM修订；
3. PART/PRODUCT及其单位、版本、生命周期和BOM位号；
4. 虚构供应来源、采购授权和采购订单行；
5. 收货事件、收货批次、质量检查与处置；
6. 库存入账、库位、状态桶和快照基线；
7. 预留、拣配、发料、现场交接、工单安装消耗；
8. 旧件返回、隔离、返修或报废；
9. 盘点、差异、对账及PCN/EOL影响事件。

每个子对象应引用已存在且有效的父对象。若测试目标就是验证孤儿引用、过期BOM或缺失审批，应把缺陷显式标为负向夹具，并隔离在专用测试分组中，不能污染正常基线夹具。

## 4. 事件时序、版本和可重放性

对具有事件性质的夹具，至少区分业务发生时间、源系统创建/更新时间、集成接收时间和测试运行时间。时间戳应采用含时区的ISO 8601表示，并在数据集清单中声明规范化策略；不能把无时区的本地时间混作UTC，也不能依靠文件行顺序推断业务先后。

事件关系至少能回答：

- 哪个源事件/测试事件触发了当前状态；
- 哪个对象、对象修订、机型配置和BOM有效期受影响；
- 事件的业务时间、接收时间、顺序号和版本是什么；
- 重放时如何识别重复事件，如何处理迟到/乱序事件；
- 冲销或补偿事件引用哪一条原始事件，是否保留原事件；
- 库存数量变化对应哪个业务事务、批次、单位和状态桶。

正常路径的时序应遵循业务依赖；负向路径可有意构造重复、乱序、迟到、部分完成、冲销或跨版本事件，但必须有独立标记、明确预期状态和隔离重置组。不得通过直接编辑最终库存余额掩盖事件处理错误。库存变化应能由受测系统定义的有效事件重放或源系统记录解释。

## 5. 测试环境分层与隔离要求

| 测试层级 | 环境边界 | 数据要求 | 允许动作与限制 |
|---|---|---|---|
| L0 静态检查 | 仓库/CI只读或临时工作区 | 项目文件、Schema和合成样例 | 不连接企业业务系统，不执行业务事务 |
| L1 组件/规则 | 本地或专用测试进程 | 固定合成夹具 | 可运行规则、转换、校验和确定性重放 |
| L2 集成/SIT | 企业批准的独立非生产实例/租户 | 已批准冻结的数据集 | 仅使用测试端点、测试账号、测试队列和模拟外部依赖 |
| L3 业务/UAT | 企业批准的UAT环境 | 冻结合成数据；如例外使用脱敏数据须单独审批 | 使用获授权测试角色验证流程，不向生产供应商/客户/设备发送真实动作 |
| L4 上线准备 | 发布评审与只读证据区 | 测试结果、缺陷、审计、回滚和运行手册 | 只进行上线准备评审；不把本测试包视为生产变更授权 |

L2/L3环境必须由系统所有者明确识别环境实例、租户、数据库、接口地址、测试队列和数据保留策略。不得仅凭URL中的“test”字样判断环境非生产。环境名称、账号、网络路由和数据落点应以企业受控清单为准。

必须确认并留证：测试环境与生产环境在身份、网络、数据库、队列、存储、作业调度和外部接口上隔离；禁止生产写入权限和生产凭证；默认禁止向生产网络、供应商、客户或机床现场发送出站业务动作。若测试依赖外部系统，应使用获批的mock/stub/sandbox端点，并验证其不会代理到生产。

任何涉及真实机床控制器、运动轴、主轴、ATC、卡盘、液压/气动或安全回路的连接均不属于本规范的常规SIT/UAT。需另行进行工程风险评估、硬件隔离、授权和专项HIL计划；禁止在生产设备上执行本套合成备件测试，禁止旁路任何防护、急停或安全联锁。

## 6. 权限、保密和日志

- 仅为测试目的开设专用身份；按角色和测试用例授予最小必要权限，使用期限结束后撤销。
- 账号、密码、API Token、私钥、证书私密部分和连接字符串不得写入数据集、CSV、Issue、日志或Git。通过企业批准的秘密管理渠道注入。
- 合成供应商、用户、机床和工单标识必须显式使用测试命名空间，例如 TEST-、SYN-、FIX- 前缀；不得复用看似真实的生产ID。
- 测试日志只记录完成审计所需的字段。对账号、个人信息、商业数据和凭证进行最小化/遮蔽；导出前进行扫描。
- 访问、审批、数据导入、重置、事件回放、清理和测试结果变更必须保留可追踪记录。
- 如使用脱敏数据，需另外记录原始数据所有者、批准依据、脱敏方法版本、风险评估、访问限制、到期日期和销毁证明；未获批准时禁止导入。

## 7. 数据导入、重置、恢复与清理

每个测试运行前应确认环境基线和数据集校验值，创建可恢复的非生产快照或采用可验证的重建流程。重置步骤应在该环境的批准变更/测试流程中执行，不能直接在生产环境运行清理脚本。

建议使用独立运行ID、租户/Schema/队列前缀或隔离命名空间，将每次运行的对象和事件限定在可清理范围。重放同一版本数据集应得到可比较的业务结果；重置后核对对象数量、关系完整性、库存初始状态、事件偏移/队列状态和审计日志。

测试结束后：
1. 导出测试报告、运行配置、数据集版本/校验值、日志索引、缺陷和审批证据；
2. 将环境恢复到批准快照或销毁专用测试资源；
3. 清除临时账号、令牌、文件、队列和测试业务记录，按企业策略保留必要审计证据；
4. 复核不存在指向生产系统的写入、消息、采购/发货通知或设备动作；
5. 由环境所有者和测试负责人确认清理结果。

数据集保留期限、日志保存期限、快照期限及安全销毁方式由企业数据所有者/安全责任人批准，不在本项目中预置统一天数或阈值。

- [测试环境就绪检查表](../../resouces/17-operation-maintenance-and-repair/spare-parts-test-environment-readiness-checklist.csv)：逐项确认隔离、权限、秘密管理、备份、mock端点、日志、恢复和清理；所有检查初始为NOT_ASSESSED。
- [合成夹具对象与事件交叉引用模板](../../resouces/17-operation-maintenance-and-repair/spare-parts-test-fixture-cross-reference-template.csv)：用合成ID连接静态对象、事务事件、时间线、预期状态和关联测试用例；不承载真实生产主键。

首次执行顺序建议为：确认环境责任人和批准范围 → 生成并审查数据集 → 冻结版本和校验值 → 环境就绪检查 → 预置数据 → 运行指定测试用例 → 导出证据 → 重置与清理。任何必需项未批准或未检查时，相关L2/L3测试保持BLOCKED，不得以“模板已填”代替环境批准。

## 9. 验收标准与未完成事项

本规范交付的仓库级验收包括：三个CSV结构稳定、列宽一致；资源路径和ASSET实体一致；文档链接和计划/索引登记完整；无真实业务ID、个人数据、密钥或生产记录。

企业环境级验收尚未执行，当前不具备以下证据：授权非生产环境清单、网络隔离证明、角色授权、备份/恢复演练、mock端点确认、已批准冻结的数据集、测试运行记录和清理签字。因此，30个端到端测试用例仍全部为NOT_RUN；本轮模板状态为未评估，不能将其解释为SIT/UAT通过或上线批准。
