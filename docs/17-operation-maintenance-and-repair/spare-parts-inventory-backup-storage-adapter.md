# 数控机床备件库存账本备份存储适配器契约

**知识ID：** KNOW-000034  
**章节：** CH17 操作、维护与维修  
**状态：** IN_PROGRESS / 仅本地与Mock合成验证  
**适用范围：** 已验证的本地库存账本备份包的供应商中立对象存储接口设计。

## 1. 设计目标与非目标

目标是把第十八轮的本地备份包与存储介质解耦，让同一套备份清单和完整性规则可以由不同Provider承载。接口只提供条件创建对象和读取对象；本轮不提供对象删除、列举、云账号配置、凭据注入、KMS/HSM、加密算法、网络客户端或生产部署。

当前实现位于 `scripts/spare_parts_backup_storage_adapter.py`，Provider契约为 `ObjectStorageProvider`，包含：

- `capabilities`：返回能力声明及其证据范围；
- `put_if_absent(key, data)`：按不可覆盖语义创建对象，同键同字节重复调用可幂等返回，不同字节必须冲突；
- `get_object(key, version_id=None)`：读取对象；有版本ID时必须精确读取所记录的版本。

接口没有delete/list，避免测试适配器意外形成批量删除或全桶扫描能力。未来真实Provider须在独立实现和变更评审中增加必要功能，不得直接把Mock接口视作云端生产驱动。

## 2. 备份对象布局与提交回执

一次备份在对象存储中包含四个负载对象：`BACKUP.json`、`COMMIT.json`、`ledger.json`、`snapshot.json`。存储前缀采用 `<prefix>/backup-<backup_id>/`，每个对象键均为相对规范化POSIX路径。

上传顺序为：先上传四个已由本地 `verify_backup()` 校验的负载对象，最后上传 `BACKUP-RECEIPT.json`。回执是这个多对象包的提交标记，记录backup ID、对象前缀、原始备份manifest摘要、各对象键/长度/SHA-256/版本ID和Provider类型。只有回执完整发布、回读并验证通过后，适配器才返回PUBLISHED。

该协议不是对象存储的多对象事务。上传中断可能留下部分负载对象，但没有回执时该备份不算已提交，也不能用于恢复。重试必须使用同一backup ID和完全相同字节；相同对象幂等复用，内容不同则失败关闭。当前没有自动清理未提交孤儿对象的接口，必须保留审计并由另行批准的生命周期/回收程序处理。

回执必须最后发布，并依赖Provider对条件创建和回执读取一致性的实际保证。若目标对象服务不支持可靠的`put_if_absent`或回读语义，必须由Provider实现额外协调机制或拒绝适配，不能弱化提交条件。

## 3. 两种Provider及其证据边界

### 3.1 FileSystemStorageProvider

本地文件Provider使用目录树承载对象键，采用同目录暂存文件、文件fsync和硬链接原子创建，提供本地同字节幂等与不同字节冲突行为。对象键拒绝绝对路径、`.`/`..`、反斜杠、符号链接和不安全父目录。

能力声明为本地文件系统条件创建；不提供对象版本控制、对象锁或云端访问能力。静态加密和传输加密标记为未知/不声明，而不是假定已经启用。原子硬链接、fsync和目录持久性仍依赖操作系统和文件系统支持；不作为跨网络文件系统保证。

### 3.2 MockObjectStorageProvider

Mock Provider在进程内存中维护对象映射，可以模拟条件创建、幂等重试、版本ID声明、对象锁声明和上传中断。它不访问互联网，不使用云凭据，也不真实执行加密、对象锁、耐久存储、跨区复制或服务端版本保留。构造参数中的能力布尔值只是测试开关，不构成供应商证据。

### 3.3 Provider能力不得被误读

Provider的能力报告必须与证据范围一起展示。`object_versioning=true`不等于对象不可变；对象锁/保留模式需要合同、API配置和实测证据；服务端加密声明不等于客户托管密钥已生效；TLS声明不等于客户端凭据、证书和端点已安全部署。未知能力保持null/NOT_CLAIMED，不可推断为支持。

## 4. 验证与恢复路径

`publish_backup()`在读取本地备份包后先将四个预期负载复制到一次性暂存目录，并对这组固定字节运行原始备份验证；验证通过后才上传，避免先验证目录、后读取文件之间的变更窗口。

`verify_stored_backup()`读取回执、校验回执自摘要、对象键布局、长度、SHA-256和精确版本ID，将负载下载到临时目录，再运行第十八轮的原始备份完整性校验。账本哈希链、快照与COMMIT关联仍由原验证逻辑负责。

`restore_from_provider()`先完成上述远端读取和完整性校验，再调用既有 `restore_backup()` 写入空白隔离目标目录；不得覆盖非空目录或直接指向生产账本目录。恢复后仍需要独立业务SoR对账，当前适配器不会做企业业务断言。

## 5. 故障与安全边界

- **部分上传：** 回执缺失时不视为完整备份；同内容重试可继续，冲突内容不能覆盖；不自动删除孤儿对象。
- **对象损坏/缺失：** 回执摘要、版本、长度、SHA-256或原始备份清单校验任一失败均拒绝验证/恢复。
- **版本固定：** 回执保存负载对象版本ID；Provider支持版本读取时按精确版本恢复，未提供版本ID的回执读取只能用于定位当前提交标记。
- **路径安全：** 本地Provider拒绝路径穿越及符号链接对象；真实对象存储Provider仍需对键编码、租户边界和服务端策略独立安全评审。
- **无删除API：** 本轮不提供删除、桶清空或自动孤儿回收，避免未经企业批准的破坏性操作。
- **无秘密处理：** 不在仓库、CSV、日志或Artifact中存储访问密钥、令牌、密码、私钥或明文数据密钥。
- **无加密实现：** 当前Provider只搬运不透明字节；`server_side_encryption`和`transport_encryption`是能力声明，不是加密执行结果。

SHA-256可检测普通内容损坏，但无外部信任根/数字签名时不能证明上传者身份，也无法抵御有权限者同时改写回执与全部负载。对象锁、账户隔离、密钥控制、供应商可用性和跨区域耐久性均需要真实Provider和企业证据。

## 6. 测试结果与后续接入门禁

自动测试使用本地临时目录和Mock Provider，覆盖上传/回执发布、同内容幂等、内容冲突、半途失败与续传、回执和负载篡改、对象缺失、版本ID固定、路径穿越、非空恢复目录拒绝和隔离恢复。CI自检报告只声明Mock上传、回读完整性和隔离恢复通过。

在开发任何真实对象存储Provider之前，应先完成：能力矩阵评审、供应商官方API/合同核验、独立账户与最小权限、凭据短期化/托管、TLS与静态加密验证、对象锁/保留策略、版本读取和条件创建一致性测试、带宽/费用/RPO/RTO实测、退出与恢复演练及安全审查。

**严格状态：** 本轮没有真实云Provider、凭据或网络访问；没有加密、远端复制、对象锁或删除操作。Mock能力不构成生产证据。`production_backup_enabled=false`，`governance_readiness=BLOCKED_PENDING_ENTERPRISE_APPROVAL`，业务断言`NOT_EVALUATED`，企业备份/恢复测试`NOT_RUN`。
