# 数控机床备件库存账本备份治理、RPO/RTO与灾备验收

**知识ID：** KNOW-000033  
**章节：** CH17 操作、维护与维修  
**状态：** IN_PROGRESS / 企业政策待批准  
**适用范围：** 备件库存账本、快照、备份副本、恢复演练和相关基础设施控制。

## 1. 目标与范围

本文件将本地备份原型扩展为可供企业决策和审查的治理框架，覆盖保留与删除、恢复点目标（RPO）、恢复时间目标（RTO）、静态/传输加密、密钥生命周期、异地存储以及灾备恢复演练。

配套资源包括四份空白决策/评估模板、一份恢复演练验收矩阵和一个本地结构校验器。模板不预置企业保留时长、RPO/RTO数值、密码算法、云厂商、区域、服务等级或职责分配。

## 2. 备份对象与职责边界

- **源账本代际：** 本地CURRENT指向的一个已提交账本/快照代际。
- **备份副本：** 从某一已验证代际导出的独立备份包；备份成功不等于异地复制成功。
- **保护副本：** 采用独立账户/权限、保留锁定或离线隔离等措施，降低源账户被攻陷时的共同损失；具体控制须依据企业威胁模型和供应商能力评估。
- **恢复副本：** 从选定备份在隔离目标环境中实际恢复并完成验证后的副本。仅通过清单校验不等于恢复演练通过。

备份政策批准主体应由企业资产/数据所有者、业务连续性负责人、信息安全/密钥管理负责人、基础设施/云平台负责人、隐私/法务或记录管理负责人按组织制度确定。模板中的角色名称是待填写的职责位，不代表已确认的企业岗位分工。

Git仓库、CI Artifact和当前本地备份目录不得自动视作企业正式备份介质。

## 3. 备份保留与删除治理

使用资源模板 spare-parts-inventory-backup-retention-policy-template.csv 逐数据域登记：

- 备份范围、数据分类、备份类型/触发频率及纳入/排除对象；
- 保留时长、计量单位、政策/合同/法规依据和复核周期；
- 法律保全/调查冻结、不可变保留、版本控制和例外处理；
- 到期判定、删除方法、执行权限、双人复核与删除证据；
- 策略所有者、批准角色、审批引用、生效时间和定期复审日期。

不得直接把“最近N代”或“保留若干天”作为企业最终保留政策。第十七轮GC中的keep_last与minimum_age_seconds只是本地目录清理参数，不能替代法定留存、合同要求、法律保全、跨区域副本和备份介质生命周期规则。

删除流程应先核实所有副本、复制队列、法律保全和恢复演练窗口，再执行并留存审批/执行证据。当前本地GC不具备企业级删除审批、双人控制或法律保全接口。

## 4. RPO/RTO目标及测量定义

资源模板 spare-parts-inventory-backup-rpo-rto-requirements-template.csv 用于记录服务级恢复目标和测量方式。

- **RPO（恢复点目标）：** 业务可接受的最大数据丢失窗口。必须指定测量起点/终点、业务时钟或事件边界、时间单位、系统时钟来源和数据一致性定义；不能简单把备份作业间隔等同于实际RPO。
- **RTO（恢复时间目标）：** 从明确的业务中断/恢复启动事件到服务恢复并通过业务验证的目标时长。必须界定计时起止点，说明是否纳入审批等待、密钥获取、网络/身份依赖、数据下载、账本校验、应用重放、对账、业务放行和故障切回。
- **按业务影响分级：** 各服务目标应由业务影响分析、依赖关系、最大可容忍中断时间、数据重建能力和运营窗口推导。知识库不提供默认分钟/小时数。
- **实测优先：** 目标批准后，恢复演练应保存真实开始/结束时间、数据截止点、实际恢复点、验证耗时、依赖等待时间和异常；报告目标值与实测值。合成自检用时不能当作生产SLA。

## 5. 加密、密钥生命周期和异地存储

资源模板 spare-parts-inventory-backup-security-key-management-template.csv 要求评审静态/传输加密范围、算法和模式的批准依据、密钥生成/托管/轮换、权限分离、双人控制、密钥备份/恢复、break-glass访问、密钥泄露响应和审计证据。

禁止在CSV、Git、日志、CI Artifact或备份包中存储密钥、口令、令牌、私钥或未脱敏秘密。

资源模板 spare-parts-inventory-backup-offsite-storage-assessment-template.csv 用于记录云账户/租户所有权、区域/司法辖区、数据驻留、网络路径、传输保护、客户端/服务端加密、不可变/对象锁、保留执行、删除保护、IAM/MFA、私有网络、恢复吞吐、出口费用、SLA证据、供应商事件通知及退出/迁移方案。

区域名称、供应商功能和SLA必须以企业采购合同、当前官方文档和实际验证为依据，不预设某个云厂商或区域。

**当前适配器边界：** create_backup()/verify_backup()/restore_backup() 仅处理本地文件系统目录；没有KMS、HSM、对象存储、云身份、TLS传输或异地复制适配器。本轮只定义供应商中立的评估字段与验收条件，不实现远端写入或密钥操作，不提供可直接接入生产的云端适配器。

## 6. 恢复演练验收及生产启用门禁

资源矩阵 spare-parts-inventory-backup-restore-drill-acceptance-matrix-v1.csv 包含10个待批准场景，覆盖备份点选择、完整性校验、密钥可用性、隔离环境、RTO测量、RPO测量、账本语义、业务SoR对账、异地副本取回、保留/删除证据。

每项测试必须引用已批准的RPO/RTO目标、恢复流程、隔离控制和证据保存位置；不适用场景也应由责任人说明理由并批准，不能默认为PASS。

**生产备份/灾备启用前必须同时满足：**

1. 数据范围、分级、备份频率、保留期、法律保全与删除审批已由责任方批准；
2. 每个业务服务的RPO/RTO目标、测量定义、依赖顺序和业务验证责任已批准；
3. 静态/传输加密、KMS/HSM、密钥恢复、密钥泄露与职责分离控制有受控证据；
4. 异地/离线/不可变副本的账户隔离、区域/司法辖区、供应商条款、恢复吞吐和退出方案已评估；
5. 恢复演练在获批隔离环境完成，账本完整性、业务对账、目标RPO/RTO与证据保留均有责任方签核；
6. 回切、失败回滚、事件响应和定期复演周期经业务连续性与系统所有者批准。

仅本地结构校验、CI PASS、manifest SHA-256通过或单个合成恢复成功，均不能使以上门禁自动转为APPROVED。

## 7. 自动校验器的含义

运行 python scripts/spare_parts_backup_governance_validator.py --root . 可执行本地结构校验；可通过 --report-json 输出JSON报告。CI运行相同校验并归档报告Artifact。

校验器检查五个CSV的列名/顺序/行宽、唯一记录ID、审批状态、APPROVED记录的审批人/依据/带时区时间戳和关键决策字段；对RPO/RTO数值作有限数值与正负范围检查；并验证10条恢复演练规格均保持PROPOSED_NOT_APPROVED和NOT_RUN。

报告result=PASS只表示模板和审批证据结构可解析；治理就绪状态始终为BLOCKED_PENDING_ENTERPRISE_APPROVAL，production_backup_enabled=false。校验器不判断企业政策内容是否合理、不检查法律适用性、不连接KMS/云服务、不发起备份/恢复/删除，也不替代安全评审或业务签署。
