# 数控机床备件库存账本备份 Provider 身份权限、分块续传与孤儿回收治理

**知识ID：** KNOW-000035  
**章节：** CH17 操作、维护与维修  
**状态：** IN_PROGRESS / 本地与Mock合成验证  
**适用范围：** 第二十轮供应商中立存储适配器的身份/权限、断点续传、对象一致性、故障恢复与孤儿对象治理扩展。

## 1. 目标与边界

本轮将备份Provider的安全与可靠性契约扩展为可测试的本地/Mock行为：主体身份与动作权限、对象前缀隔离、元数据审计、分块上传续传、分块校验、版本固定、前缀范围内只读盘点，以及未完成备份/分块会话的回收审批准备。

实现仍在 \`scripts/spare_parts_backup_storage_adapter.py\`。FileSystem Provider只依赖宿主OS文件权限；Mock Provider模拟主体/租户/动作/对象前缀ACL和内存审计，不实现真实身份认证。新增能力不等于真实对象存储供应商已经通过安全审查。

本轮明确不做真实凭据处理、IAM云端策略部署、网络连接、KMS/HSM、加密实现、已完成对象删除、自动保留/删除策略执行或生产账号接入。

## 2. 身份与最小权限模型

Provider能力声明新增：

- \`identity_authentication\`：身份来源与认证机制描述；
- \`authorization_model\`：动作与资源范围的授权模型；
- \`tenant_isolation\`：租户隔离能力，未知保持null；
- \`audit_logging\`：审计日志能力及证据边界；
- \`multipart_upload\`：是否支持分块上传；
- \`scoped_inventory\`：是否支持受限前缀的对象元数据盘点。

Mock Provider的主体、租户、允许动作和允许前缀仅用于验证策略判断。默认允许前缀限于测试命名空间 \`cnc/\` 与 \`ch17/\`。每次读、写、前缀枚举和分块会话访问都检查授权；拒绝记录只写入principal ID、tenant ID、action、object key和ALLOW/DENY，不记录对象负载、密码、令牌或密钥。

真实Provider接入时应区分写入主体、恢复读取主体、盘点审计主体和安全管理员。写入主体通常只需要在被授权的对象前缀上创建对象/分块并读取自身提交回执；恢复主体需要精确版本读取；盘点主体只获得指定前缀的元数据枚举权限；删除或保留策略管理权限必须另行隔离，不能与日常备份写入身份合并。具体动作、前缀、MFA/工作负载身份绑定、凭据生命周期、审计保留、break-glass和职责分离均须由企业安全责任方批准。

访问密钥、令牌、密码、私钥和明文数据密钥不得进入仓库、CSV、日志、异常、Artifact或测试夹具。

## 3. 分块上传与断点续传契约

新增可选 \`MultipartObjectStorageProvider\` 协议，支持：

1. \`begin_multipart_upload(key, upload_id)\`：按确定性upload ID创建/复用未完成会话；
2. \`put_multipart_part(..., part_number, data, expected_sha256)\`：校验分块摘要；同编号同内容重复调用幂等，不同内容冲突；
3. \`list_multipart_parts(key, upload_id)\`：仅列出指定上传会话已完成的分块元数据，不提供全桶枚举；
4. \`complete_multipart_upload(...)\`：校验分块编号连续、汇总长度和对象SHA-256后，再按不可覆盖语义提交最终对象；
5. \`abort_multipart_upload(key, upload_id)\`：只放弃尚未完成的分块会话暂存，不得删除已经完成/发布的对象。

适配器根据payload摘要与object key派生确定性upload ID。重试时先读取会话内已完成分块的编号、长度和摘要，仅补传缺失分块；发现相同分块编号内容不同、编号越界、缺块、乱序或汇总摘要不符时失败关闭。完成对象仍须进入第二十轮的manifest/receipt校验链。

当前代码默认阈值和part size只是可配置的软件行为默认值，不是生产带宽/成本/服务端限制建议。真实Provider的最小/最大分块、最后一块约束、会话有效期、并行度、续传窗口、校验算法和费用均待供应商文档及实测确认。

## 4. 版本、读一致性与故障恢复

备份回执固定记录每个负载的version ID；读取主体必须按回执记录的版本读取，不能默认取“最新版本”。如果Provider不支持版本化读取，必须确认对象不可覆盖和读后写语义能满足等价安全边界，否则不应宣称支持版本固定。

Mock仅模拟强读后写一致性，不证明云服务/跨区复制/缓存层具备相同语义。真实接入时须定义：
- 条件创建成功后回执何时可见；
- 对象版本列表/精确版本读取是否存在延迟；
- 重复请求、超时但服务端实际成功时的幂等行为；
- 分块上传会话过期、服务端限流、网络断开、校验失败和客户端重启后的续传恢复；
- 读回校验失败时是否重试、隔离或标记不可用。

故障注入测试至少覆盖上传第N块后进程中断、同一分块重复、分块摘要错误、缺块、乱序、合并对象摘要不匹配、完成请求响应丢失、回执对象未出现、对象版本变化、读权限被撤销和前缀授权越界。任何恢复成功都必须以重新读回并验证完整备份包为条件。

## 5. 孤儿对象与分块会话只读盘点

适配器新增 \`ScopedInventoryProvider\` 可选接口，只允许对用户明确指定的对象前缀返回元数据（对象键、长度、SHA-256、版本ID）；分块会话清单也必须限制在该前缀。盘点结果不包含对象正文。

按backup ID归组后，状态至少区分：
- \`UNCOMMITTED_ORPHAN_CANDIDATE\`：存在备份负载对象但缺少最终回执；
- \`PUBLISHED_VERIFIED\`：回执和全部负载存在，且完整性验证通过；
- \`PUBLISHED_PACKAGE_INCOMPLETE_OR_UNEXPECTED_OBJECTS\`：存在缺失负载或额外对象；
- \`PUBLISHED_INVALID\`：回执、对象摘要、版本或原始备份完整性校验失败；
- \`INCOMPLETE_MULTIPART_UPLOAD\`：尚未完成的上传分块会话，由独立会话清单返回。

该分类只表示盘点时观察到的结构事实，不能仅凭“没有回执”推断对象已过期或可删除。必须查明写入任务状态、业务持有者、备份保留政策、法律保全/调查冻结、恢复窗口、跨区域副本状态、对象锁、重复/并发任务和审计证据。

盘点结果统一标记 \`PROPOSED_NOT_APPROVED\`，\`reclamation_executable=false\`。当前实现没有已完成对象的delete接口，也没有自动孤儿回收功能。分块会话abort仅可清理未完成的会话暂存，不具备删除已提交对象的能力。

## 6. 孤儿回收审批工作流（仅设计）

受控回收必须先导出盘点清单并由数据所有者、备份服务所有者、安全/合规责任方审核。批准证据至少包括：明确对象键与版本、业务数据域和分类、备份ID及回执状态、未完成任务调查、适用保留政策和法律保全检查、仍可用的恢复点、回收理由、执行身份、双人复核、执行窗口、回滚/补救方案和操作日志。

审批状态与执行状态分开管理。审批不等于执行，执行完成还须保存服务端删除/生命周期执行证据和复核结果。不得以对象年龄、模拟时间或CI通过作为自动回收依据；本模板不设定保留期限或安全阈值。
