# 数控机床备件系统集成、字段映射与数据治理

**知识条目：** KNOW-000028（in_review）  
**关联任务：** CH17-T004 第二轮  
**适用范围：** 面向数控机床运行维护、维修和备件业务的 ERP、CMMS、EAM、PLM/PDM、采购门户及知识库之间的数据边界与映射设计。  
**文档性质：** 项目内部的厂商中立参考架构和治理建议，不代表任何软件产品的标准数据模型或已实现的系统集成。

## 1. 目标与系统边界

本专题把上一轮建立的备件主数据、关键度、库存补货、替代审批、生命周期和维修消耗模板，进一步转化为可供企业信息化项目实施的字段映射、数据质量、库存决策和责任治理要求。

首先明确三个不同层次：

1. **主数据与配置对象：** 机床实物实例、机型、BOM、零件、商品化产品、供应商、受控文档和配置修订。
2. **业务事务与事件：** 采购订单行、收货、检验、库存移动、预留、领料、退料、维修工单、替代审批、工程变更和供应商PCN/EOL通知。
3. **知识与证据：** 字段定义、流程说明、来源元数据、官方链接、模板、技术评审结论和可合法保存的验证证据。

知识库用于保存可复用的解释、数据字典、关系定义和模板；它**不是**ERP库存账、采购订单系统、CMMS维修工单系统或PLM配置基线的替代品。真实业务记录应保存在企业选定的权威系统中，知识库只保留必要的非敏感引用、方法说明及合法可公开的证据。

### 1.1 系统职责候选划分

下表是项目设计时的职责候选，不是对任何企业现状的推断。每个业务对象、甚至同一对象的不同字段，都必须在集成设计中明确唯一权威来源（System of Record，SoR）。

| 系统类别 | 可承担的业务职责（需项目确认） | 不应未经确认地假设 |
|---|---|---|
| ERP / MRP | 物料/采购主数据、采购订单、收货、库存账、财务和供应商交易 | 不一定是设备配置、维修诊断或OEM技术批准的权威源 |
| CMMS | 维修工单、维护任务、维修活动、故障报告、工时和工单备件消耗 | 不一定是库存、物料工程修订或采购合同的权威源 |
| EAM | 设备台账、设备层级、资产状态、安装位置、寿命和维护管理 | 不一定覆盖完整BOM、采购履约或零件工程更改 |
| PLM / PDM / BOM系统 | 设计BOM、制造BOM、工程修订、ECO/ECN及适用性 | 不一定掌握现场库存余额、实际安装件和维修执行结果 |
| 供应商门户 / OEM渠道 | 正式报价、交期确认、产品变更通知、停产通知、服务支持和技术公告 | 门户可见或经销商口头反馈不自动等于正式OEM批准 |
| 知识库 | 术语、数据字典、受控模型、来源元数据、方法、模板和审查记录 | 不作为企业实时交易主账，也不应复制客户/供应链机密 |

同一对象在不同组织的系统职责可能不同。项目必须形成SoR决策表，记录字段级权威系统、数据责任人、技术接口人、更新方向和冲突处理规则。

## 2. 与本知识库数据模型的映射边界

当前仓库的实体类型及关系类型已能表达备件管理中需要引用的主要静态对象，无需为本轮模板提前增加新的全库实体类型或关系谓词。

| 业务对象 | 当前知识模型候选 | 说明 |
|---|---|---|
| 机床产品型号 | MACHINE | 整机型号/系列，不代表单台实物 |
| 单台机床资产 | MINST | 设备实例；序列号、客户和位置等敏感字段需受控 |
| 配置BOM | BOM | 受控机型、配置、修订和有效范围的BOM |
| 物理备件/零件 | PART | 有物料号、图号或可独立管理的物理零件/装配件 |
| 商品化部件/产品型号 | PRODUCT | 例如驱动器、电机、主轴或标准商品部件 |
| 制造商/供应商/经销商 | VENDOR | 通过角色属性区分，不能混为同一角色 |
| 受控手册/图纸/通知元数据 | DOC | 只记录合法可保留的文档元数据和出处 |
| 实际归档的模板或附件 | ASSET | 文件实体；完整文档仍按版权规则归档 |

可复用的关系谓词包括：INSTANCE_OF、MODEL_OF、HAS_PART、PART_OF、MANUFACTURED_BY、SUPPLIED_BY、DISTRIBUTED_BY、DOCUMENTED_BY、VERIFIED_BY、DERIVED_FROM 和 SUPERSEDES。只有在真实对象、主体/客体类型、适用范围和证据齐全时才创建具体关系记录。

**库存余额、批次、库位、采购单行、收货行、库存移动、预留、领料/退料事务、维修工单和审批工作流实例属于业务事务对象。** 当前全库实体枚举没有为这些事务逐一建模。本轮不将其伪装为 PART 或 PRODUCT，也不创建没有真实业务对象的 REL 记录。它们应在源系统中保持事务身份，通过系统标识和外部键与 MINST、MACHINE、BOM、PART、PRODUCT、VENDOR 等主数据关联。若未来确有跨章节知识图谱建模需求，应先进行全库数据模型评审、关系语义分析和Schema兼容性测试。

## 3. 字段映射设计

### 3.1 外部标识与主键

每个跨系统映射至少保留以下识别信息：

- 源系统标识、租户/公司/组织范围、对象类型、源系统原始ID，以及源记录修订或版本（如适用）。
- 知识库实体ID（仅当该业务对象确实已登记为知识实体时）；不得仅因存在ERP料号就自动创建知识实体。
- 映射规则ID、映射版本、生效时间、失效时间、责任人、审批引用和最近核验时间。

外部标识不应只用一个裸数字或短代码。不同系统可能复用相同编码；建议以“源系统 + 租户/组织范围 + 对象类型 + 源ID + 必要的修订标识”构成外部引用的作用域。不得把客户密钥、访问令牌、个人账号或不必要的个人信息写入映射表。

### 3.2 关键对象映射清单

| 源业务对象 | 规范对象/关联对象 | 必要关联键 | 主要一致性检查 |
|---|---|---|---|
| 设备资产台账 | MINST、MACHINE | 资产外部键、机型键、序列范围/配置键 | 机型与设备实例关联有效；资产状态和配置时间有效 |
| 工程BOM行 | BOM、PART、PRODUCT、MACHINE/SUBSYS | BOM编号/修订、父项、子项、位号、有效期 | 父子层级、数量单位、修订和适用配置一致 |
| 备件物料主数据 | PART 或 PRODUCT | 物料类型、企业物料号、OEM料号/修订 | 物料身份唯一；零件与商品化产品不混淆 |
| 供应商/制造商目录 | VENDOR、PART/PRODUCT | 供应商ID、制造商ID、供应关系/渠道角色 | 制造商、授权经销商、实际供货方角色有证据 |
| 库存快照/库存流水 | PART + 源事务外部键 | 物料、组织、仓库、库位、批次/序列、事务ID | 余额与过账流水可对账；不可用数量分桶清楚 |
| 采购订单/收货批次 | PART、VENDOR + 源事务外部键 | PO行、供应商、物料、收货批次、数量单位 | 订单、收货、检验、退货与在途状态不重复计算 |
| 维修工单/备件消耗行 | MINST、PART/PRODUCT + 源事务外部键 | 工单、设备、备件行、批次/序列、领退料事务 | 领料和实际安装、拆下件、复验、退库/报废可追溯 |
| 替代件/工程更改 | 原件PART、候选PART/PRODUCT、BOM | 原件—候选件、机型/序列/配置、BOM位号、ECO | 批准范围、有效期、软件/接口版本和验证证据匹配 |
| PCN/EOL/服务通知 | PART/PRODUCT、VENDOR、DOC | 通知编号、发布方、产品修订、适用日期 | 通知来源、发布时间、最后采购/发货/服务日期有证据 |

### 3.3 映射规则

1. **粒度先行：** 明确每一行代表一个物料修订、BOM行、仓库快照、库存移动、批次、维修工单备件行或生命周期通知，不允许混合粒度。
2. **字段级SoR：** 对物料名称、技术修订、库存余额、采购交期、工单状态、实际安装件等字段分别指定权威系统。多系统都可编辑时必须设计主从优先级或显式人工冲突处理。
3. **单位与代码集：** 保存原始单位、规范单位、换算规则版本和审批来源；单位不兼容时禁止静默转换。状态代码必须保存源值与目标值映射及版本。
4. **空值语义：** 区分未知、未采集、不适用、尚未审批、确认为无和历史上不存在；不得把空字符串、0、N/A互相替代。
5. **有效时间：** 区分业务生效时间（valid/effective time）、源系统更新时间和知识库接收时间；修订变化保留历史，不用最新值覆盖历史适用范围。
6. **重复与幂等：** 为接口消息或事务定义稳定的源事务ID/事件ID及去重策略；重放同一消息不得重复增加库存或重复领料。
7. **双向更新：** 默认不做无约束双向同步。明确单向主数据分发、事务回传或经批准的例外字段；冲突必须进入审查队列。
8. **数据安全：** 对客户设备序列、安装地点、采购价格、合同、供应商联系人和生产数据分类分级；知识库仅保存完成技术追溯所必需且获准公开的最小信息。

详细映射使用 [spare-parts-enterprise-system-field-mapping-template.csv](../../resouces/17-operation-maintenance-and-repair/spare-parts-enterprise-system-field-mapping-template.csv)。

## 4. 库存账、事件流水与跨系统对账

库存快照是特定时点的状态，库存移动是带业务时间和过账状态的事件。两者不能互相替代。系统集成应首先确定组织、仓库、库位、物料、批次/序列、所有权（自有/寄售/供应商寄存）和库存状态等维度。

### 4.1 数量口径

上一专题中的字段口径继续适用：

- quantity_available_calculated = quantity_on_hand_total - quantity_reserved - quantity_allocated - quantity_quarantined
- 若组织政策采用库存位置口径：inventory_position_calculated = quantity_available_calculated + eligible_open_purchase_orders - backorders

必须在接口规范中明确“eligible open PO”的筛选条件，采购订单未确认、已关闭、已取消、已收货或已被其他在途口径覆盖的数量不得重复计入。

账面结存的事件桥接可表示为：

closing_book = opening_book + posted_receipts + posted_returns + posted_transfer_in - posted_issues - posted_transfer_out - posted_scrap + approved_adjustments

这只是帮助检查事件完整性的符号口径。企业系统可能存在寄售、借料、在途、质检待验、负库存、跨组织所有权转移和单位换算等特殊规则，必须在本地会计/库存政策和接口设计中明确，不把此式直接当作所有系统的过账算法。

### 4.2 三条对账链

- **库存事务 → 库存账：** 同一组织、物料、仓库、库位、批次/序列和计量单位下，已过账事件与账面余额一致；未过账、撤销和冲销事件分别处理。
- **库存账 → 实物盘点：** 以盘点时点和冻结/动态盘点策略对齐账面与实物；差异按企业批准的容差、复盘、审批和调整流程处理。此处不预设差异阈值。
- **维修工单 → 备件消耗：** 工单计划用件、仓储领料、实际安装、拆下件、退库/返修/报废、旧件核心返还和维修后复验之间可逐行追踪；工单关闭前对异常缺失进行处置。

预留、分配、隔离和在途应分为独立状态或数量桶。不得把“预留”同时从实物总量和可用量中重复扣除；也不得把质检未放行批次当作可用库存。所有数量必须带基本单位及换算来源。

## 5. 数据质量与对账控制

数据质量规则至少覆盖身份、关系、适用性、数量、时间、状态、来源和访问控制。推荐先从阻断性强的键和事务完整性规则开始，再根据企业实际系统质量分层启用。

附带的规则表是**建议控制目录**，不是任何ERP/CMMS/EAM产品的既定规则，也不是不经评估即可全部启用的自动阻断配置。每条规则须由数据所有者确认适用系统、检测频率、阻断/告警策略、容差、责任人和处置SLA；有安全或合规影响时优先采用人工复核与保守停用策略。

| 规则域 | 检查重点 | 建议处理 |
|---|---|---|
| 唯一性 | 源键作用域唯一、规范实体映射唯一、重复供应商/料号 | 阻止重复建档或进入主数据复核 |
| 引用完整性 | BOM、设备、部件、供应商、工单和批次引用存在 | 关键引用缺失时隔离该记录/事务 |
| 适用性 | 机型、序列范围、选件、软件版本、BOM修订和有效期一致 | 配置不匹配时不得自动批准替代或发料 |
| 单位与数值 | 单位可换算、精度和小数位规则明确、数量非异常 | 禁止无来源换算；异常按本地政策复核 |
| 事务完整性 | 过账、冲销、撤销、重放、移动方向及数量守恒 | 防重复过账；差异进入对账队列 |
| 批次与序列追溯 | 收货批次/序列、检验、领料、安装、拆下件去向 | 追溯断链时限制放行或关闭 |
| 生命周期 | PCN/EOL来源、发布时间、最后采购/发货/服务日期 | 缺少正式证据时保持待核实 |
| 替代审批 | 原件/候选件、批准范围、有效期、工程变更和验证证据 | 未批准或超范围的替代不得转为有效 |
| 来源与审计 | SoR、映射版本、更新时间、责任人和变更记录 | 无法解释的覆盖更新进入人工审查 |
| 权限与保密 | 角色权限、敏感字段、导出和外部共享范围 | 遵循最小权限并保留访问审计 |

完整的建议规则编号、校验逻辑、证据与责任字段见 [spare-parts-data-quality-and-reconciliation-rules.csv](../../resouces/17-operation-maintenance-and-repair/spare-parts-data-quality-and-reconciliation-rules.csv)。

## 6. 库存策略决策数据集

库存策略必须以“零件 + 仓库/地点 + 适用机型/配置范围”为决策单元，必要时进一步拆分批次、服务区域或供应渠道。一个零件在不同服务区域可能具有不同需求、交期、运输约束和服务目标，不宜将全企业一个参数无差别套用。

### 6.1 决策输入

至少采集并记录以下输入及其来源日期：

- 在役设备数量、机型/序列/选件分布、安装基数变化和剩余服务承诺；
- 有效的历史领用、退料、报废、缺件、紧急采购及工单消耗；区分计划维护需求和随机故障需求；
- 需求时间窗口、停机/缺货影响、可检测性、冗余、维修恢复时间和关键度评估方法版本；
- 正式采购交期、交期波动、供应商确认日期、唯一来源、MOQ、订货倍数和运输/进口条件；
- 可修复/可翻新/可周转属性、维修周期、返修成功率证据、库存寿命、保质期和储存环境要求；
- 成本、预算、保管条件、呆滞/过期损失与质量隔离风险（仅在企业授权范围内使用）。

需求窗口应足以覆盖适用机型的使用与维修周期，并标记缺失数据、停产设备、策略变更和历史配置差异。没有可靠数据时，明确记录数据不足，不以假设平均值、模拟需求或未经核验的交期生成“建议库存”。

### 6.2 策略选择

可评估的候选策略包括按需采购、订货点/安全库存、定期复核、最小/最大库存、供应商寄售/协议库存、修复周转池、关键件专库存储及停产最后采购。它们只是可选策略名称，选用前必须验证业务约束、系统能力、合同条件和风险承担方。

每个策略记录：

1. 适用对象、机型/序列/配置范围、仓库和计量单位；
2. 需求、交期、供应风险和关键度数据源及有效窗口；
3. 计算方法/策略版本、参数单位、假设、例外及压力测试；
4. 采购约束、保质期/储存限制和修复周转安排；
5. 设备、工程、维修、采购、仓储、质量和财务角色的批准记录；
6. 生效日期、下次复核触发条件、策略变更历史及回滚办法。

安全库存、订货点、最小/最大量、服务水平、预测窗口、需求分布假设和复核周期全部是企业/部件/地点特定决策，必须来自批准政策和真实数据，本专题不提供通用数值或默认阈值。

决策使用 [spare-parts-stock-policy-decision-template.csv](../../resouces/17-operation-maintenance-and-repair/spare-parts-stock-policy-decision-template.csv) 记录；关键度模板和库存流水模板仍分别承担风险输入与实际库存快照/事务记录，不应将三者混成一张表。

## 7. 审批职责与状态控制

### 7.1 RACI责任原则

建议至少明确以下职能角色，但不预设任何企业的人员姓名或组织架构：

- 设备/资产所有者：确认机床范围、停机影响和资产适用性；
- 维修/维护负责人：确认工单需求、现场拆换事实和复验闭环；
- 机械/电气/控制工程：确认技术兼容性、参数/接口影响和工程变更；
- 质量/安全职能：确认质量风险、来料/过程检验及安全影响；
- 采购/供应链：确认供应来源、合同、交期、PCN/EOL和采购策略；
- 仓储/库存控制：负责收货、批次、库位、盘点、隔离、领退料和事务对账；
- OEM/授权服务方：在合同、保修、OEM程序或安全要求需要时提供技术确认；
- 数据所有者/系统管理员：管理字段定义、映射版本、访问权限、接口和审计。

每一项关键流程至少指定一个最终负责（A）角色，并明确执行（R）、会签/咨询（C）和知会（I）。角色配置由组织批准；涉及安全相关部件、保修影响或法规义务时，不能以采购或库存角色替代工程/安全审批。

### 7.2 建议状态机

以下状态词汇为项目建议，不宣称是行业标准或某一软件产品内置状态。企业实施前应映射至源系统的状态代码、审批权限和有效动作。

- **主数据：** DRAFT → DATA_VALIDATION → TECHNICAL_REVIEW → ACTIVE；发现问题可转 RESTRICTED 或 ON_HOLD；不再适用时经审批转 DEPRECATED，最终 ARCHIVED。
- **替代审批：** PROPOSED → TECHNICAL_REVIEW →（必要时）OEM_APPROVAL_PENDING → QUALITY_RISK_REVIEW → VALIDATION_PENDING → APPROVED_WITH_SCOPE。失败可转 REJECTED；批准失效、范围改变或原依据撤销时转 EXPIRED/WITHDRAWN。任何批准都必须绑定具体适用范围和有效期。
- **库存质量状态：** AVAILABLE、RESERVED、ALLOCATED、QUARANTINED、IN_TRANSIT、RETURNED_PENDING_INSPECTION、OBSOLETE、SCRAPPED。这些状态需明确是否互斥及其与实物量、可用量、财务所有权的关系。
- **生命周期事件：** 收到正式PCN/EOL通知后先登记来源与受影响范围，完成安装基数/需求/供应风险评估，再决定最后采购、替代/改造、维修支持或退役策略。通知收到不等于自动作出停产或替代结论。

状态转换要记录操作者/角色、时间、前后状态、原因、证据、审批记录和有效范围。禁止直接把待审批替代件写入正式BOM或可发料主数据。

## 8. 实施顺序与验收门槛

推荐以只读盘点起步，不在首次接入时写回企业生产系统：

1. 取得数据所有者授权，确认系统边界、接口许可、环境和数据分类。
2. 对各系统做对象/字段盘点，确定字段级SoR、外部键、粒度、时间语义、状态字典和单位。
3. 建立映射表与规则目录，使用脱敏样本进行离线校验。
4. 对账主数据、BOM适用性、库存快照/流水、PO/收货、工单领退料和生命周期通知；形成差异清单。
5. 由业务所有者、工程/质量、采购/仓储和系统负责人签署映射及规则版本。
6. 先只读或影子运行，观察重复消息、迟到数据、撤销冲销、单位换算、批次追踪和历史回补。
7. 写回接口只能在权限、幂等、回滚、审计和生产变更审批完成后单独启用；本专题不代表已经连接或执行了任何生产系统接口。

验收至少要求：所有关键字段有唯一SoR；主键/外部键无歧义；BOM/配置适用性和有效时间可解释；库存数量与事务可对账；维修工单消耗可以追溯到批次和实际安装件；替代审批不能越权或跨范围复用；PCN/EOL有可核验来源；数据差异有责任人与处置结果；接口变更具有版本、审批和回滚证据。

## 9. 本轮未实施事项与后续输入

本轮只新增厂商中立的映射、数据质量和决策框架，没有访问或连接用户企业的ERP、CMMS、EAM、PLM/PDM或供应商门户，也没有导入真实业务数据。因此：

- 没有建立具体企业系统的API、消息队列、批处理作业、账号或接口连接；
- 没有创建真实库存快照、事务流水、采购单、供应商报价/交期或维修工单；
- 没有确定字段级SoR、映射转换、数据清洗容差、对账频率或异常SLA；
- 没有确定关键度分数、库存策略、预测窗口、安全库存、订货点、最小/最大量或最后采购数量；
- 没有分配企业真实RACI人员，也没有批准任何替代件或PCN/EOL迁移决策。

后续实施需要经授权的目标机床BOM/OEM备件目录、脱敏ERP/CMMS/EAM对象与字段清单、库存快照与事务样本、采购/收货/交期历史、维修工单和PCN/EOL文件。导入前必须先完成数据权利、保密和访问授权审查。
