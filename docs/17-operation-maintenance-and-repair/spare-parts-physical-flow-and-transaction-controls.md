# 数控机床备件实物流转、事务控制与责任矩阵

**知识条目：** KNOW-000029（in_review）  
**关联任务：** CH17-T004 第三轮  
**适用范围：** 从备件需求提出到采购、收货、检验、入库、预留、领用、安装、旧件返还、维修/报废和库存对账的通用业务控制。  
**文档性质：** 项目内部参考流程；控制点、角色分配和状态均需由企业结合实际系统、合同、质量政策及OEM要求批准，不代表行业标准或某个ERP/CMMS的内置流程。

## 1. 流程目标与控制原则

本专题将前两轮建立的备件主数据、系统映射、数据质量和库存策略，落到一条可以审查的实物流转与业务事务链。核心目标不是规定某种ERP的屏幕操作，而是确保每一件备件从需求到最终处置时，身份、数量、配置适用性、质量状态、责任人、审批和证据都能连续追踪。

流程必须区分三类事实：

1. **实物事实：** 备件实际到货、移动、存放、发出、安装、拆下、返修或报废的事实。
2. **账务/系统事实：** 对应的收货、入库、预留、出库、转移、退料、调整和冲销事务是否已在权威系统成功过账。
3. **技术/质量事实：** 料号与修订、机型/序列/配置适用性、检验状态、替代批准、维修结果和放行证据。

实物已移动不代表系统已过账；系统已有库存余额也不代表货物已完成检验或满足安装适用性。两者不一致时必须进入差异处理，不应通过直接改余额或覆盖历史记录掩盖。

### 1.1 控制原则

- **一事一事件：** 每个业务事件使用源系统稳定的事务ID/事件ID；同一事件重放不得重复增加/扣减库存。
- **状态不越级：** 待检、隔离、待修、待处置和过期件不得自动变为可用库存；替代件审批通过前不得按正式件发放。
- **配置先校验：** 领料/安装前核对机型、序列范围、选件、BOM修订、软件/接口版本和有效日期。
- **批次追溯按风险适用：** 对OEM、法规、合同、质量或企业策略要求追踪批次/序列号的部件，贯通收货至设备安装及拆下件去向；不得擅自将所有零件都假设为序列号管理。
- **权限分离：** 采购、收货、检验、库存保管、技术替代批准、维修安装和库存调整的职责需由组织批准并避免不适当的单人闭环。
- **记录不可覆盖：** 差错更正使用冲销/反向事件和原因记录；保留原事件、修正事件、批准和时间戳。
- **安全优先：** 维修现场作业须执行具体机床OEM文件、现场风险评估、合格授权人员及适用的危险能量控制/LOTO；本流程不提供电气隔离、泄压、拆装、吊装或其他危险作业步骤，也不允许旁路联锁。

## 2. 端到端生命周期阶段

| 阶段 | 业务控制目标 | 关键记录/证据 | 不满足时的处置 |
|---|---|---|---|
| 需求提出 | 需求可关联设备、故障/维护任务或批准的库存策略 | 需求单、维修工单、维护计划、缺件/停机影响 | 需求来源不清时退回补充，不自动生成采购量 |
| 技术与配置确认 | 物料身份和目标设备适用性明确 | PART/PRODUCT、受控BOM、机型/序列/配置、OEM目录 | 配置或修订不匹配时暂停选件/发料 |
| 采购审批与下单 | 供应商、交期、合同和采购数量经授权 | PR/PO行、报价/交期确认、批准策略版本 | 未批准的紧急采购按企业例外流程处理并补录审计 |
| 到货接收 | 实物、随货文件和订单行一一对应 | 收货单、PO行、包装标签、料号/修订、批次/序列 | 身份不符、数量差异或文件缺失时隔离待处理 |
| 来料检验与放行 | 质量状态有明确结论 | 检验计划、证书/报告（如要求）、不合格记录、放行批准 | 未放行不得计入可用量 |
| 上架与储存 | 位置、环境、寿命和保管状态受控 | 仓库/库位、批次、储存条件、有效期、保管记录 | 超储存条件或身份不明转隔离/评估 |
| 预留与拣配 | 需求、设备配置和替代批准有效 | 预留行、工单、设备实例、拣配扫描/复核 | 不适用或未批准物料不得拣发 |
| 发料/转运 | 出库和实物交接一致 | 出库事务、领料人、批次/序列、目的地和交接证据 | 交接差异进入库存/工单对账 |
| 安装/消耗确认 | 实际安装与领料计划及设备配置闭环 | 实际安装件、设备实例、BOM位号、工单、OEM程序引用和复验 | 未取得授权/程序/放行证据时不关闭维修工单 |
| 拆下旧件处理 | 旧件去向和状态明确 | 拆下件身份、故障现象、返修/待检/报废决定 | 不得将拆下件直接作为可用库存 |
| 返修/翻新/报废 | 处置及质量放行可追溯 | 返修报告、检验/测试记录、报废审批及库存事务 | 未经批准不得重新入库或销账 |
| 库存盘点/对账 | 实物、账面和业务事件差异得到解释 | 盘点表、交易流水、调整/复核审批 | 未查明差异不得无依据调整 |
| 生命周期变更 | PCN/EOL等通知转化为受控风险行动 | OEM/正式供应商通知、受影响BOM、安装基数和决策 | 来源不充分时仅标待核实，不宣告停产 |

## 3. 事件模型与事务记录

### 3.1 建议的公共事件字段

以下字段用于定义接口或企业源系统字段映射，并非要求所有系统采用相同数据库表结构。字段级权威系统、必填条件和敏感等级须由项目确认：

| 字段组 | 建议字段 | 控制目的 |
|---|---|---|
| 事件身份 | source_system、source_tenant、event_type、source_event_id、source_event_version | 构造稳定的外部事件标识并防止重复过账 |
| 业务时间 | occurred_at、recorded_at、posted_at、effective_at | 分开记录实物发生、源系统接收、账务过账和业务生效时间 |
| 业务对象 | part_external_key、product_external_key、machine_instance_key、bom_revision、work_order_key、po_line_key | 关联规范主数据及源系统事务 |
| 数量与单位 | quantity、uom、conversion_rule_version | 数量、基本单位、换算和精度可复核 |
| 库存维度 | organization、warehouse、location、ownership、lot、serial、quality_status | 确定库存地点、所有权、追溯和质量桶 |
| 方向与状态 | from_location、to_location、from_status、to_status、posting_status | 区分实物移动、质量状态变化和系统过账状态 |
| 审批与证据 | approval_reference、inspection_reference、engineering_change_reference、oem_document_reference | 证明业务动作具有适用批准和技术依据 |
| 执行审计 | actor_role、created_by_reference、reason_code、source_record_version | 保留角色、原因和原始记录版本；避免不必要的个人数据 |
| 更正链 | reversal_of_event_id、corrected_by_event_id、correction_reason | 冲销和更正与原始事件关联，禁止覆盖历史 |

批次/序列追踪、照片/证书、签名、供应商/价格、客户设备信息等字段应按适用合同、法规、质量体系和数据分类策略确定。非必要敏感数据不得复制到知识库。

### 3.2 库存状态与数量口径

实物库存总量、质量隔离、预留、已分配、在途、退回待检、寄售/借料和所有权应分开建模。不要把库存状态、财务所有权和地理位置压缩成一个单字段。

可用量仍沿用上一专题的口径：

- quantity_available_calculated = quantity_on_hand_total - quantity_reserved - quantity_allocated - quantity_quarantined
- 企业政策如采用库存位置口径：inventory_position_calculated = quantity_available_calculated + eligible_open_purchase_orders - backorders

在途量只有满足企业批准的采购订单状态、供应商确认和交期条件时才可计入相应库存位置口径；已收货、取消、关闭或重复计入的数量不得重复加入。

库存事务事件桥接可以按企业批准的符号规则检查期末账面量：

closing_book = opening_book + posted_receipts + posted_returns + posted_transfer_in - posted_issues - posted_transfer_out - posted_scrap + approved_adjustments

此式仅作核对思路，不替代企业会计、库存政策和ERP过账逻辑。寄售、负库存、所有权转移、在途和质检待验必须按源系统的业务规则处理。

## 4. 关键流程控制门

### G1 需求与适用性确认

需求必须关联可审查的业务原因：维修工单、计划维护任务、库存策略建议、缺件事件或批准的项目备件准备。技术/配置复核至少确认料号、修订、BOM位号、机型与序列范围、选件以及必要的软件/接口版本。缺少受控BOM或OEM目录时，不应把名称相近或图片相似当成兼容证据。

### G2 采购与供应来源确认

采购侧核实供应商身份/角色、合同与授权渠道（如要求）、正式报价、承诺交期、MOQ/订货约束、运输和储存条件。供应商口头说明、搜索摘要或经销商网页缓存不能替代正式交期或OEM技术批准。采购策略版本、需求窗口和批准人应可回溯。

### G3 收货、检验与库存可用状态

收货核对订单、料号/修订、数量、包装与随货文件；批次/序列要求应在收货时建立追溯。质量/技术不合格、身份不明、受损或文件缺失的物料进入隔离/待检状态。只有完成适用检验并得到授权放行后，才可按企业规则转为可用库存。此处不设通用检验项目、抽样比例或接受阈值。

### G4 预留、拣配与发料

发料前校验：需求有效、设备实例/配置匹配、物料状态为可发、批次/序列满足追溯要求、替代批准在适用范围和有效期内、目标工单/领料授权有效。预留、分配和出库事件分开记录，不能把未实际发出的预留误报为已消耗。

### G5 现场安装与实际消耗确认

现场由合格授权人员按机床OEM受控程序及风险控制实施。库存系统只记录必要的物料身份、批次/序列、数量、工单、设备实例、BOM位号、安装时间和程序/审批引用，不将数据库记录当作操作许可。实际安装件与计划件不同、出现额外消耗或替代件时，必须按企业变更/替代审批闭环。维修后复验及设备放行仍按维修工作包执行。

### G6 旧件回收、返修和报废

拆下件应先明确身份和来源，记录其原安装设备/位号、工单、故障现象与批次/序列。后续可进入待检、返修、供应商RMA、保留分析、返库待判或报废等处置。只有返修/翻新后的适用检验和批准完成，方可按企业政策重新分配为可用件。报废须有授权处置和对应库存/财务事务，避免账物不符。

### G7 盘点、调整与差异关闭

盘点前明确快照时点、范围、计量单位、冻结或动态盘点规则和在途/未过账事务处理。对差异先检查重复过账、迟到消息、未过账收发、单位换算、错位库位、批次、所有权和质检桶；调整需有原因、复核及授权。不得设置跨企业通用盘点容差或未经批准自动抹平差异。

### G8 PCN/EOL及库存策略复核

收到正式PCN/EOL/服务支持变化通知后，记录发布方、通知编号、发布时间、受影响产品修订和适用机型配置；结合安装基数、剩余服务承诺、真实领用/失效记录、正式交期和储存寿命开展影响评估。最后采购、替代、改造、修复周转或退役决策需有批准记录，不得仅由网页状态或单一渠道消息触发自动采购。

## 5. 异常与补偿处理

| 异常 | 立即控制目标 | 后续处置与关闭证据 |
|---|---|---|
| 到货与PO料号/修订不一致 | 隔离相关实物，防止可用库存误计 | 采购/工程确认退货、纠正PO或经批准变更；保留差异和最终结果 |
| 数量/包装/批次差异 | 分开记录实收数量和账面数量，避免先行过账错误 | 供应商调查、收货更正或索赔；保留原始收货与冲销链 |
| 检验不合格/证书缺失 | 设置质量隔离，不允许发料 | 按质量处置决定返供、返工、让步（仅经适用批准）或报废 |
| 系统接口重复事件 | 使用源事件ID和幂等键拦截重复过账 | 回查既有处理结果，不重复产生库存移动 |
| 库存账与实物不符 | 暂停无依据调整，确认盘点时点与未过账事件 | 复盘、责任调查、批准调整和审计关闭 |
| 设备配置不匹配 | 停止该次自动发料/替代放行 | 工程核对受控BOM及有效性；形成批准或拒绝结论 |
| 工单计划件与实际安装件不同 | 不把计划量覆盖为实际量 | 记录实际安装、旧件和偏差；补做适用技术审批/复验 |
| 旧件去向不明 | 保持待判/隔离，不重新入库 | 找回追溯链，形成返修、分析、退回或报废结论 |
| 供应商PCN/EOL来源不明 | 标记待核实，不自动改生命周期状态 | 向OEM/正式供应渠道核实通知、适用修订和日期 |
| 关键责任人/审批缺失 | 保持流程停留在待审状态 | 指定企业授权角色并补齐审批证据；禁止倒签或代签 |

更正事务应优先采用源系统支持的冲销/反向记录；如果源系统不能原生冲销，应记录补偿事件、原事务引用、审批和完整审计理由。不得删除已经对外引用或参与财务过账的历史事件。

## 6. RACI职责分配

本轮提供的RACI模板预填的是**可讨论的角色建议**，不是对用户所在企业人员/岗位的认定。企业需要根据组织结构、授权制度、合同、法规和安全职责调整。每项活动至少应有一个A（最终负责），R（执行）可以有一个或多个；C为会签/咨询，I为知会。不要将个人姓名、账户或联系方式填入公开仓库模板。

建议角色代码：

| 角色代码 | 职能 |
|---|---|
| ASSET_OWNER | 设备/资产所有者，确认资产范围和停机影响 |
| MAINT_LEAD | 维修/维护负责人，确认工单、领料需求、实际安装及复验闭环 |
| ENGINEERING | 机械/电气/控制/产品工程，确认技术适用性、BOM及替代工程依据 |
| QUALITY | 质量职能，负责检验、质量隔离、不合格处置和质量放行 |
| SAFETY | 安全职能，评估相关危险源和安全功能影响 |
| PROCUREMENT | 采购/供应链，负责供应商、订单、交期和PCN/EOL沟通 |
| WAREHOUSE | 仓储/库存控制，负责收货、库位、批次、盘点及领退料事务 |
| OEM_SERVICE | OEM/授权服务方，按合同/保修/技术要求提供确认；其意见不替代企业内部授权 |
| DATA_OWNER | 业务数据所有者，负责主数据、SoR、字段定义和数据质量政策 |
| IT_INTEGRATION | 信息化/接口负责人，负责集成、权限、幂等、监控和技术审计 |

模板中的建议分配均须经企业批准。安全相关零件、功能安全、保修约束、关键质量特性和特殊储存要求应追加适用的独立审查，不可只依赖普通采购/仓储签字。

## 8. 本轮交付边界与后续输入

本轮建立厂商中立流程控制矩阵和建议RACI样表，没有接入实际业务系统，也没有实施企业盘点、收货、检验、领料或现场安装。因此：

- 未创建真实采购订单、收货单、库存移动、批次/序列、领料/退料或维修工单记录；
- 未指定真实系统SoR、事件接口、事务状态代码、盘点频率、库存调整阈值或差异SLA；
- 未批准任何企业实际岗位RACI、替代件、来料检验标准或报废处置权限；
- 未提供机型级危险能量控制、拆装/吊装/调试步骤、扭矩/压力/参数或验收阈值；
- 本轮模板状态仍为PROPOSED，不能当作生产系统控制已启用或维修现场SOP。

后续需要授权的企业角色/审批制度、实际ERP/CMMS/EAM状态字典、收货/库存移动/工单事务样本、目标机型受控BOM及OEM资料，才能把建议控制点转换为企业正式流程和系统验收用例。
