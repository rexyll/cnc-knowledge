# 数控机床备件管理、替代审批与生命周期闭环

**知识条目：** KNOW-000027  
**版本：** 0.1  
**适用章节：** CH17 — 操作、维护与维修  
**状态：** 通用管理框架与空白数据模板；待企业主数据、目标机型及供应证据映射

## 1. 目的和边界

本专题把维修活动与备件供应管理连接起来，建立从设备安装基线、部件主数据、关键度评估、库存策略、采购补货、替代件审批、入库/领用、维修后复验到停产风险和维修反馈的追溯链。

本专题定义记录对象、状态流、决策输入和审核控制，不提供任何品牌/型号的真实备件号、供应商、价格、交期、最小库存、补货点、安全库存、替代兼容结论或剩余寿命。所有数值、供应承诺、生命周期状态和技术兼容结论必须来自可追溯的OEM文件、正式供应商证据、企业历史数据或批准的工程评审。

不得把相似外形、相同名称、单一尺寸匹配、销售页面中的“替代/升级”描述或未经审核的厂商交叉表，直接视为可装机的等效替代件。不得为降低库存成本而移除安全相关或法规要求的备件控制。

## 2. 备件管理对象与主数据关系

| 数据对象 | 一条记录代表什么 | 关键追溯关系 |
|---|---|---|
| 备件主数据 | 一个可独立管理的零件/总成及其版本 | PART/PRODUCT、BOM位置、机型配置、序列范围、OEM来源 |
| 关键度评估 | 某备件在指定设备/配置/应用范围内的一次评估 | 失效影响、冗余、可检测性、历史故障、供货风险、批准策略 |
| 库存与补货 | 一个备件在某仓库/库位/批次/状态下的库存快照或交易汇总 | 主数据、批次、供应商、采购单、工单领用和盘点记录 |
| 替代审批 | 原件与候选件在明确适用范围内的一次工程批准 | 原/候选件修订、OEM声明、接口证据、工程变更、验证结果 |
| 生命周期记录 | 一个备件的制造商生命周期和停产风险快照 | PCN/EOL通知、last-time-buy、服务支持、安装基数、迁移计划 |
| 维修消耗反馈 | 一次维修事件中备件拆下、安装、领用和反馈记录 | 工单、设备实例、旧/新件批次、复验、库存交易和故障记录 |

备件主数据是权威身份记录；库存记录不应复制并维护另一份零件技术主数据。实际安装配置、维修历史和设备序列号应关联企业受控的MINST/工单记录，不在公共知识正文中暴露客户、个人或敏感资产标识。

## 3. 生命周期闭环

建议按下列顺序运行企业内部流程；具体角色和审批等级由组织质量体系、合同、适用法规及OEM要求确定。

1. **建立候选主数据：** 从受控BOM、备件目录、铭牌、OEM服务文件或正式采购记录确认零件身份、修订和适用机型范围；证据不完整时保留候选状态。
2. **确定应用与关键度：** 评估失效后果、冗余、可检测性、停机影响、历史失效、修复可能性和供应风险。采用企业批准的方法与权重，不引入通用分数阈值。
3. **批准库存策略：** 综合设备安装基数、需求历史、交期证据、供应波动、MOQ/订货倍数、保修/合同义务、储存寿命和停机风险，形成可追溯的补货规则。策略批准后才填写安全库存、补货点、最小/最大量。
4. **采购和收货：** 按批准供应商与采购条款采购；收货核对制造商、料号、修订、批次/序列号、合格证明、包装、储存和有效期。身份或质量证据不一致时隔离，不得直接转为可用库存。
5. **替代件控制：** 先建立替代审批案例，确定机型/序列/选件/BOM适用范围，审查所有相关机械、电气、热、流体、材料、软件/固件、安全和维护接口。需要OEM批准或法规符合性证明时必须取得；完成工程批准和验证前不得作为已批准替代件发放。
6. **工单领用与装机：** 领用交易绑定工单、设备实例、数量、批次/序列号和拆下件标识。安装后按维修影响矩阵实施OEM要求的复验；未通过或证据不全不得放行。
7. **旧件处置与反馈：** 记录旧件返回、分析、修复、保修索赔、返厂、隔离或报废结果；将重复失效、实际消耗、停机时间和补货需求反馈到库存策略与CH18故障分析。
8. **生命周期监视：** 跟踪制造商PCN/EOL通知、最后采购日期、最后发货日期、服务/维修支持结束时间、供应商状态和已批准后继件；形成受控迁移或最后采购决策。
9. **定期复核：** 对主数据、库存准确性、超期/呆滞库存、替代审批有效范围、生命周期状态和关键备件策略按企业制度复审，并保留复核证据。

## 4. 关键度评估与库存策略

关键度不是仅由采购金额、历史领用次数或零件价格决定。建议至少审查以下维度：

- **安全与合规后果：** 失效是否影响安全功能、人员防护、法规/合同要求或风险控制措施。
- **生产与质量影响：** 失效是否导致整机停机、降级运行、加工质量偏离、工件/刀具损失或交付延误。
- **冗余和可检测性：** 是否有可用冗余、故障是否能及时检测、是否可安全降级运行。
- **维修与恢复能力：** 现场是否可修复、是否需要OEM服务、专用工装、校准或外送维修。
- **供应风险：** 正式交期、唯一来源、MOQ、供应中断、停产通知、运输/进口限制和替代验证难度。
- **安装基数和需求：** 在役设备数量、机龄/配置分布、真实消耗记录、失效记录和计划检修需求。

评估应保留原始输入、方法版本、评估范围、审批人和复核日期。安全或法规影响显著的部件应按组织批准的风险流程处理，不能通过简单加权分数被低库存策略覆盖。

库存决策可采用企业批准的最小/最大、订货点、定期复核或按需采购等策略。无论采用何种策略，补货参数必须有来源：需求窗口、交期确认日期、交期波动、安装基数、服务目标、批量约束、保质期和预算约束等。不得直接套用跨机型通用的“常备数量”或未核实交期。

### 4.1 库存数量口径

建议将同一库存快照中的实物分桶定义清楚：

- `quantity_on_hand_total`：库内实物总数，包含已预留、已分配和隔离品；
- `quantity_reserved`：为已批准需求保留但尚未发出的数量；
- `quantity_allocated`：已分配到工单/设备但尚未完成出库的数量；
- `quantity_quarantined`：质量、身份、有效期或合规状态未放行的隔离数量；
- `quantity_available_calculated`：可用量，按本模板的分桶定义计算：
  `on_hand_total - reserved - allocated - quarantined`；
- `inventory_position_calculated`：供补货决策使用的库存位置。若企业政策采用该口径，可按：
  `available + eligible_open_purchase_orders - backorders` 计算。必须明确哪些在途采购单符合“eligible”，并避免与已收货数量重复计入。

公式只说明字段口径，不替代ERP/MRP或企业库存政策。若系统采用不同的库存分桶、借料/寄售、在途、质检待验或维修周转件口径，应在数据字典中记录并统一映射。

### 4.2 补货参数控制

安全库存、订货点、最小/最大库存、MOQ、订货倍数、预测需求和交期均应记录单位、统计窗口、公式/策略版本、来源日期、审批人和生效日期。需求和交期历史不足时标记数据不足，不能伪造平均值或自动生成建议数量。易老化/有有效期/需特殊储存的部件还应检查先到期先出、批次追溯和报废风险。

## 5. 替代件审批与技术证据

替代审批必须建立原始件和候选件的明确配对，并绑定适用设备配置和BOM位置。按适用性审查：

- 机械安装接口、尺寸/公差、基准、载荷、刚度、转速/惯量、方向和运动范围；
- 材料、热处理、表面处理、腐蚀/污染环境、温度和使用寿命要求；
- 电气额定值、保护等级、接插件、引脚定义、接地、屏蔽和电磁兼容；
- 固件/协议/参数、CNC/PLC映射、驱动版本和配置变更；
- 液压/气动压力等级、流量特性、介质、密封和润滑兼容性；
- 安全功能、认证/符合性、风险评估以及对原安全架构的影响；
- OEM更换/升级声明、工程计算、试验计划、验收来源和维修后验证结果。

审批结果应限定机型、序列号范围、配置、软件版本、BOM位号、工况和有效期限。某机型的批准不得自动扩展到另一型号或不同修订。若没有OEM明确替代声明，应按企业工程变更流程完成设计审查、风险评估和适用验证；无法证明兼容时保持BLOCKED/REJECTED。

## 6. 生命周期与停产风险管理

生命周期记录应基于带日期的制造商通知、正式经销商/供应商确认、合同或采购事实更新，不以论坛信息或网页缓存推定停产状态。至少跟踪：

- 生命周期状态及来源、PCN/EOL通知编号和发布时间；
- last-time-buy截止日期、最后发货日期、维修/服务支持结束时间；
- 唯一来源/供应商数量、已安装基数、备件可得性和风险评估；
- 已批准替代件、迁移/改造计划、验证和停产切换批准；
- 最后采购记录、剩余库存处置、返修/翻新方案和合同影响；
- 责任角色、下次复核日期、风险缓解措施与关闭证据。

“制造商标记为停产”“渠道暂时缺货”“企业停止采购”和“备件已无服务支持”是不同状态，不得混为一个结论。最后采购数量应由安装基数、剩余服务承诺、失效/消耗数据、储存寿命、批次风险和批准预算共同决定，模板不预填数量。

## 7. 维修消耗与反馈闭环

每一次备件消耗都应关联维修工单和设备实例，记录旧件、新件、数量、单位、批次/序列号、库存事务、返修/报废去向和维修后复验。一个工单更换多个部件时按“工单—备件行项目”分别记录；一个部件拆换涉及多批次时也应拆分行项目，避免丢失批次追踪。

反馈至少应流向：
- **库存/采购：** 实际领用、退库、报废、缺件、紧急采购、补货请求和交期偏差；
- **维修/维护：** 重复更换、失效间隔、可修复性、维护任务或检查策略调整建议；
- **质量/供应商：** 来料问题、批次异常、质量索赔、供应商纠正措施和OEM技术反馈；
- **故障诊断：** 失效模式、根因证据和重复故障趋势链接CH18，不把单次相关性直接写成根因；
- **BOM/配置：** 实际安装件和替代审批回写受控BOM/配置记录，保留变更历史。

## 9. 状态、权限与审计控制

以下状态名是本项目建议的工作流词汇，不宣称为行业标准：

- 主数据：`DRAFT`、`UNDER_REVIEW`、`ACTIVE`、`RESTRICTED`、`DEPRECATED`、`ARCHIVED`；
- 替代审批：`DRAFT`、`TECHNICAL_REVIEW`、`OEM_APPROVAL_PENDING`、`APPROVED_WITH_SCOPE`、`REJECTED`、`EXPIRED`、`WITHDRAWN`；
- 库存：按仓库系统的可用、预留、已分配、质检/隔离、在途、退回待检、报废等互斥状态管理。

建议区分主数据维护、技术审批、采购审批、收货检验、库存保管、维修领用和最终放行职责。关键记录变更应保存前后值、变更原因、审批引用和时间戳；禁止直接覆盖历史批次、替代批准或设备安装配置记录。

## 10. 当前交付边界与后续输入

本轮只建立通用流程、字段模板和审计口径。尚未提供具体机床型号/序列范围、OEM备件目录、真实BOM、安装基数、采购历史、供应商报价/交期、库存快照、PCN/EOL通知或现场维修工单，因此：

- 没有创建真实PART/PRODUCT/MINST实体、真实备件料号、供应商或库存余额；
- 没有确定关键度分数/等级、库存策略、订货点、安全库存、最小/最大量或最后采购数量；
- 没有批准任何替代件或声明任何跨机型兼容；
- 没有标记实际部件为已停产/仍有支持，也未形成实机维修反馈验证。

**CH17-T004保持IN_PROGRESS。** 后续应导入经授权的目标机型BOM、OEM备件目录、企业库存与消耗历史、供应商正式交期/PCN/EOL资料和维修工单，再逐项填充并经设备、工程、质量、采购等角色审批。
