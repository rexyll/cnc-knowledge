# CNC Knowledge 统一知识实体模型

> 文档状态：CORE-001交付版  
> 模型版本：1.0  
> 适用范围：全库22个知识章节  
> 说明：这是本知识库内部的数据治理约定，不宣称其为行业标准或厂商官方数据模型。

## 1. 设计目标

将知识库从彼此孤立的文章和附件，组织为可检索、可关联、可追溯的知识网络。采用“实体主记录 + 关系记录 + 来源记录 + 专题正文/资源文件”的结构：

- **实体（Entity）**描述一个可独立识别的对象，例如机床型号、厂商、零件、材料、标准或故障模式。
- **关系（Relationship）**描述两个实体之间有方向的事实，例如机床型号由厂商制造、零件采用某材料、某驱动支持某通信协议。
- **来源（Source）**记录支撑实体或关系的外部资料、标准、测试记录或工程证据。
- **知识正文（Knowledge Article）**负责解释原理、背景、方法和判断；通过实体ID引用主记录，不复制其他实体的权威数据。
- **资源文件（Asset）**记录仓库中实际保存的图片、动图、图纸、PDF、Office文档、CSV及其他附件；来源记录与资源文件记录不得混为一谈。

## 2. 核心建模原则

### 2.1 区分类型、型号、产品与实物

- **MTYPE**：机床类别，例如数控车床、立式加工中心、五轴联动加工中心。
- **MACHINE**：厂商定义的整机产品型号/系列。它描述产品规格及配置范围，不代表某一台具体设备。
- **MINST**：实际交付或安装的一台物理机床，可关联序列号/资产号、交付配置、安装地点和维护记录；敏感标识应按保密要求处理。
- **VENDOR**：法人或组织实体。制造商、经销商、集成商、供应商和服务商是组织角色属性，不要为同一法人重复创建多个厂商实体。
- **BRAND**：品牌身份，与拥有品牌的法人组织分离；同一厂商可以拥有多个品牌，一个品牌也可能经历品牌归属变更。
- **PRODUCT**：其他商品化产品型号，例如CNC控制器、伺服驱动器、电机、编码器、导轨、主轴、刀具或测头。

### 2.2 一个实体只有一个权威主记录

- 每个实体分配一个稳定ID；名称、型号别名、语言翻译和文件路径均不能代替ID。
- 主记录放在实体所属章节或公共数据登记中；其他章节通过ID链接和关系记录引用。
- 发现重复实体时先比较制造商、型号、版本、规格和来源，再登记合并关系；保留被合并ID的状态和主记录跳转，不复用旧ID。
- 尚不能确认是否为同一对象时保留独立候选记录，并标记待核实，不因名称相似而合并。

### 2.3 分类树与关系图分开

分类解决“它属于哪一类”；关系解决“它与谁存在什么联系”。分类路径可以调整，实体ID和已确认事实关系不能随意随之变化。具体的型号、部件、厂商、材料、接口、标准和案例都以实体及关系表达。

### 2.4 适用条件必须成为关系限定信息

关系可能只对特定机型、配置、软件版本、地区、时间范围或工况成立。此类条件记录在关系的qualifiers中，不要把有条件的结论写成无条件兼容或普遍适用。

## 3. 实体主数据字段

通用字段以data-model/entity.schema.json为准。

| 字段 | 含义 | 约束 |
|---|---|---|
| entity_id | 唯一ID | 分配后永久稳定，不复用 |
| entity_type | 实体类型 | 必须来自登记的类型枚举 |
| canonical_name | 规范名称/主名称 | 同一实体只保留一个首选名称 |
| english_name | 英文名称 | 未知时可空 |
| aliases | 别名、历史名称、型号写法 | 不将别名另建成重复实体 |
| description | 简明定义 | 说明边界，不写未经证实参数 |
| primary_chapter | 主归属章节 | CH01～CH22中的一个 |
| related_chapters | 关联章节 | 可多选；用于导航，不代替关系记录 |
| classification_path | 分类路径 | 采用受控分类，分类调整不改ID |
| tags | 检索标签 | 不作为唯一分类依据 |
| lifecycle_status | 生命周期状态 | candidate / active / deprecated / merged / archived |
| verification_status | 核验状态 | unverified / in_review / verified / disputed / rejected |
| created_at / updated_at | 创建和更新时间 | ISO 8601日期时间，建议含时区 |
| verified_at | 最近核验时间 | 未核验时为空 |
| valid_from / valid_to | 事实有效期 | 适用时填写，不等同于资料发布日期 |
| source_ids | 来源ID列表 | 引用SRC记录 |
| attributes | 类型专属字段 | 由所属章节数据字典定义，字段必须有语义 |
| notes | 备注 | 记录边界、缺失和待确认事项 |

## 4. 实体生命周期与核验状态

生命周期和核验状态是两个独立维度：

- **candidate**：刚发现的候选对象，信息不足，但有继续研究价值。
- **active**：当前知识库承认并使用的记录；不代表所有属性均已实测。
- **deprecated**：对象仍有历史意义，但已停产、被替代或不再推荐。
- **merged**：重复实体已经并入另一主记录；保留ID和跳转目标，不复用ID。
- **archived**：长期保留但不再维护的历史记录。

核验状态分别表示unverified、in_review、verified、disputed、rejected。只有证据充分且适用范围清楚的记录才可标为verified。厂商公开规格可核验“厂商声明”，但不能自动证明该数据已经独立实测。

## 5. ID分配规则

1. 格式为PREFIX加六位十进制序号，例如PART-000123、VENDOR-000007。
2. 序号在同一前缀内单调递增；分配前检查实体登记表和已有数据文件，避免重复。
3. ID不包含章节号、厂商名、型号、版本、年份、状态或路径等可能变化的信息。
4. ID一经分配永不复用；记录改名、停产、合并或迁章均保留原ID。
5. 不确定对象先标记candidate；不要为猜测的实体批量预分配ID。
6. 关系记录使用REL-000001等独立序号；来源记录使用SRC-000001。
7. 文档中出现的示例ID仅用于说明格式，不对应真实厂商、机型或部件。

## 7. 数据存储约定

- 解释性知识使用Markdown。
- 实体、关系、来源等有嵌套属性的数据记录采用JSON，并符合本目录的JSON Schema。
- 固定列、规则扁平的数据目录可采用CSV，使用UTF-8并保持稳定列名。
- 关系以独立记录保存，避免在实体主记录中硬编码大量反向引用。
- 文件名和正文链接可包含实体ID，但ID才是稳定身份。
- Schema升级必须记录变更原因、兼容性和迁移方式，不得静默更改字段语义。

## 8. 典型实体与关系示例（仅为结构示意）

- 某机床型号MACHINE-000001 — MODEL_OF → 某机床类型MTYPE-000001。
- 某实物机床MINST-000001 — INSTANCE_OF → 某机床型号MACHINE-000001。
- 某零件PART-000001 — USES_MATERIAL → 某材料MAT-000001。
- 某产品PRODUCT-000001 — MANUFACTURED_BY → 某组织VENDOR-000001。
- 某设备/软件 — USES_PROTOCOL → 某通信协议PROTO-000001。

在正式实体数据录入之前，以上ID均为模型示例，不对应真实产品。
