# 知识库质量门禁与覆盖度审查

> 规则版本：1.0
> 适用范围：全库22个知识章节
> 自动检查：scripts/knowledge_lint.py
> CI入口：.github/workflows/knowledge-quality.yml

## 1. 质量管理目标

质量检查不只是Markdown语法检查，而是确保知识可查证、可关联、可定位、可维护。采用自动检查和人工技术审查结合的方式。

- 自动检查负责目录结构、ID唯一性、Schema基础约束、关系引用、来源引用、内部链接和资源归档位置。
- 人工审查负责技术正确性、来源强度、适用边界、参数条件、安全、版权、内容覆盖和工程可用性。
- 只有通过适用的自动和人工检查，才可以把任务节点标记为DONE。

## 2. 自动质量门禁

| 门禁ID | 检查内容 | 阻断级别 | 通过条件 |
|---|---|---|---|
| QG-01 | 22章目录、章节TaskPlan和resouces映射 | ERROR | 每章正文README、TaskPlan和资源README均存在；章节计划继承根Guide/Limit |
| QG-02 | 实体类型、ID前缀、JSON格式和记录字段 | ERROR | 实体类型目录与Schema一致；ID唯一、文件路径匹配、必填字段和枚举正确 |
| QG-03 | 关系谓词和实体引用 | ERROR | 谓词在受控目录中；subject/object实体存在；REL ID唯一；引用来源存在 |
| QG-04 | 来源记录和证据分类 | ERROR | SRC ID唯一；标题、发布者、访问日期、权利状态、权威等级和证据性质有效 |
| QG-05 | Markdown内部链接 | ERROR | 本地相对链接目标存在且不允许越出仓库；外部URL可用性由人工或后续网络检查 |
| QG-06 | 资源位置与文件引用 | ERROR | 图片、动图和完整资料归档于正确resouces章节；ASSET路径有效；权利状态有记录 |
| QG-07 | 章节覆盖度矩阵 | ERROR | 22章各有且只有一条覆盖记录；数值和成熟度等级合法 |
| QG-08 | 内容质量与工程安全 | MANUAL | 技术审查、来源定位、参数边界、版权、安全和工程可用性通过 |

脚本只使用Python标准库，不要求安装第三方包。当前尚未录入技术知识时，实体、关系和来源记录数量为零是允许的；但目录、Schema、链接和覆盖矩阵必须完整。

## 3. 执行方式

在仓库根目录执行：

    python -m unittest discover -s tests -v
    python scripts/knowledge_lint.py --strict

GitHub Actions在main分支push、目标为main的pull request以及手动触发时执行相同检查。外部网站可用性不会在离线脚本中验证，不能把“链接语法通过”写成“外部网站可访问”。

## 4. 结果分级

- ERROR：必须修复，禁止关联任务标记DONE。
- WARNING：需要评估并记录原因；本版脚本暂不产生WARNING。
- INFO：统计信息，不影响通过状态。

脚本输出结构计数和错误清单。空数据集不会因此报错；真实数据录入后会自动执行实体、关系、来源和资源引用完整性检查。

## 5. 章节覆盖度等级

| 等级 | 名称 | 判定条件 |
|---:|---|---|
| 0 | not_started | 只有目录或计划，没有经过审核的知识正文；初始化脚手架不计入覆盖度 |
| 1 | inventory | 完成章节分类、主题清单、核心术语或实体盘点 |
| 2 | foundational | 有来源支持的基础概念、原理、结构和系统边界 |
| 3 | detailed | 形成可追溯的参数、型号、接口、材料、BOM或结构化技术数据 |
| 4 | operational | 具有适用范围明确的操作、设计、测试、安装、维护或故障诊断内容 |
| 5 | reviewed | 完成跨章节关联、来源复核、技术审查、资源权利检查和定期复核 |

等级是章节成熟度摘要，不代表所有章节都必须拥有相同数量的字段或文章。不得因目录、模板或未经审核的AI草稿而提高等级。

## 6. 覆盖矩阵字段

文件：docs/coverage/CHAPTER-COVERAGE.csv

- chapter_id、chapter_slug：章节身份。
- coverage_level、coverage_label：当前成熟度。
- knowledge_articles：已审核知识文章数。
- verified_entities、verified_relationships：通过核验的实体和关系数量。
- source_records、asset_records：来源及资源登记数量。
- last_reviewed_at：最近章节审查日期。
- next_priority：下一优先任务。
- status、notes：任务状态和说明。

初始矩阵将全部22章设为0级not_started。这是对当前内容状态的真实记录，不表示知识体系没有计划或目录。

## 7. 人工技术审查清单

每次知识文章或数据条目准备标记完成时，审查人必须检查：

1. 定义、原理、结构和术语是否准确，是否混淆不同机型、品牌或版本。
2. 每项关键参数是否记录单位、条件、适用范围、数据属性和来源定位。
3. 厂商声明、独立测试、实验室结果、现场实测和工程经验是否明确区分。
4. 是否有不适用条件、不同配置差异、未知项和争议项的说明。
5. 机械、电气、液压/气动、旋转部件和维修操作的危险提示是否完整。
6. 图片、图纸、动图、完整文档的来源、版权和保存权限是否明确。
7. 关联的实体、关系、BOM、标准、故障、程序和资源是否正确。
8. 是否有重复内容、断链、过时版本或未经证实的绝对化结论。

## 8. 任务完成定义

任务状态变为DONE前，至少应具备：

- 自动质量脚本通过，或每条例外都有说明与批准记录。
- 人工技术、来源、安全和版权审查完成。
- 对应章节覆盖矩阵更新，完成状态与内容成熟度一致。
- TaskPlan及当日TaskHistory更新，记录交付物、验收依据和提交SHA。

## 9. 初始覆盖状态

当前22个知识章节均为0级not_started。下一阶段按章节任务计划推进真实知识采集；每有可审查的正文、实体、关系、来源或资源新增，才更新相应覆盖计数。
